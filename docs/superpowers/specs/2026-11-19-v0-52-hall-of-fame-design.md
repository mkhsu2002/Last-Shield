## 三種做法與推薦

1. **推薦：新賽季連擊倍率＋四類英雄館。** 以持續無失誤連擊換取更高倍率，撞擊歸零；所有人使用同一份新規則。讓百萬成為高手可挑戰的里程碑，同時保留每日短局。成本是新規則版本與完整驗分／UI 平衡工作。
2. **保留目前計分。** 可先做英雄館與百萬資格判定，但不能保證任何人能實際達到，錄影可能無法完成；也可能形成不可達的產品目標。
3. **新增耐力模式。** 延長生存與獨立耐力榜，避免改每日規則，但多一套模式、驗分與教學，分散這次每日遊戲的焦點。先不採用。

不採用帳號特權、直接改分數或讓某個帳號使用不同規則。單純全局放大數字也不能證明玩法進步。

## 新賽季連擊計分的候選模型

保留目前每顆隕石的基礎分數、重型加成、Overdrive 加分、連擊判定與傷害邏輯，對每次 clear 套用該次擊碎後的連擊倍率：

| 連續擊碎數 | 倍率 |
| --- | ---: |
| 1–9 | 1× |
| 10–24 | 2× |
| 25–49 | 5× |
| 50–74 | 10× |
| 75–99 | 25× |
| 100 以上 | 50× |

每次撞擊使 combo 與倍率回到起點。Overdrive 擊碎延續 combo，但不會憑空增加完美能量；同批擊碎逐顆依事件順序計分，不能全批偷用最後一顆倍率。教學練習維持固定規則且不列入任何英雄榜。

以上是**待校準模型**，不是核准上線數值。以相同 bank 策略的 clear／impact 事件順序，只在離線分析累加假設倍率（原 DefenseRun.score 完全不變），三天試算分別為 **1,341,310／1,146,340／1,166,020**。分析同時核對原計分結果與既有 simulateDefense 完全一致。這顯示存在合理的研究方向，不能當作實玩、獲證或達成百萬的證據。

實作後擴大到至少 30 天與現有七種策略，檢查高手、帶反應延遲與初學者的差異；實際原生 UI 遊玩必須完成百萬局才能宣告錄影目標可交付。倍率只在新規則生效，舊分數不乘上倍率、不轉成新賽季紀錄。

## 英雄館範圍與榜單

第一階段各 subreddit 有自己的英雄館。正式展示館為既有 r/last_shield_dev；私人 staging 完全隔離。Devvit Redis 按 installation 隔離，跨所有 subreddit 的全球榜需要另建共用服務，這次不暗中加入外部後端或假稱已經全球共享。

英雄館頁面有每日冠軍、歷史前百、百萬英雄三個分頁，沿用現有查看排行榜入口；當日榜仍保留鄰近分差與追分。資料從功能啟用日起累積，缺少的舊紀錄不補造。最多顯示前百，不等於只能儲存一百名：保留每位自願參與者的精簡最佳紀錄，以便刪除或成績更新後正確補位。

- **每日冠軍**：UTC 當日結束後再等待既有最長 2 小時交卷期限；此後才可定案。最高分相同者並列，無人有效提交的日期顯示無紀錄。初期採請求觸發、具游標的限量結算；沒有分鐘級 cron、沒有假冠軍。每日榜過期前已需有可結算的持久摘要與日期索引，不能等 30 天 TTL 過後才找消失資料。
- **歷史前百**：每帳號只列最佳有效單局，分數由高到低、同分並列。以規則賽季區分；歷史頁可切舊賽季，不把舊規則分數當成新規則比較。每筆記錄含達成日期、賽季與帳號；新的個人最佳以交易更新，較低分不覆蓋。
- **本日最高 HUD**：已驗分的最高分與玩家名，含自己時仍顯示；多人同分顯示其中一名加並列人數，完整名單在榜單。每局開始鎖定 challenge day，跨午夜仍顯示同一日榜。無紀錄或離線時提供真實狀態；不在每幀或每秒輪詢。這是最近讀取的榜首，不宣稱即時多人對戰。
- **百萬英雄**：單局分數必須嚴格 **>1,000,000**，必須自然完局並經 server replay 接受。每帳號只領一次本賽季資格，保留首次達成時間及之後最佳分；加入順序按伺服器實際首次公開登錄順序，不保留 K 專用第一名。若移除資料，對應公開紀錄與證明須一併撤銷／隱藏。

## 頒證、長期典藏與分享

- 百萬局結束並提交成功後顯示成就解鎖。領取與公開登錄使用明確的「領取證書並加入英雄館」動作，說明長期保留公開帳號及成績；一般日榜提交不自動擴大成永久留名。
- 既有 30 天日榜與新的長期公開典藏分開。新登錄明確自願，提供撤回／移除；「長期」表示不隨每天重置或 30 天到期，不承諾 app 停止服務後仍永久存在。README、Privacy、Terms 及實際刪除 API 必須同步部署後才開放。
- 證書為遊戲內成就：Neo Babylon Citizen，包含驗證的 u/RedditUsername、達標分數、日期、賽季、公開證書編號及 Neo Babylon 視覺。玩家自填稱號另列，不冒充驗證的 Reddit 帳號。
- 頒證 server 從已驗分且綁定 actor 的紀錄產生，不接受 client 指定分數／得主。重試回同一編號與 issuedAt，與 audit、英雄榜寫入同一交易邊界。若後端失敗，UI 不能先顯示已正式領取；提供安全重試，不重複頒證。
- 證書編號是公開查驗識別，不是登入憑證。圖片可供下載，但可編輯的圖片不作為唯一證明；遊戲內可用證書編號查伺服器公開紀錄，已撤回則顯示失效。
- **分享證書**以一次點擊開啟系統分享選單，由玩家選平台與確認。先預生成圖片以保留 user gesture；實測 navigator.canShare、Web Share 與 iframe permissions policy。若 Reddit／瀏覽器不支援檔案分享，提供下載 PNG 與複製戰績連結。不能承諾所有社群皆能自動直發，也不偷偷發留言。
- 先沿用原始遊戲貼文連結與可讀證書編號，不假定 URL query 可傳進 Reddit WebView。若後續要 QR／直達個人證書，需另有實測的公開查驗路由，不產生帶憑證的分享 URL。

1. 校準並測試連擊倍率，暫定新 RULES_VERSION survival-8；只在核准設計後實作。日期主題及玩法保持 v0.51 基礎，新增倍率 HUD／大分數排版與失誤回饋。
2. 新增 HallService 與持久 compact data model：per-user best、日摘要、已結算日期索引、證書／公開撤回狀態、個人資料反向索引。新契約 community-3；所有 client／server／API DTO 同步。內部 userId 不混進公開輸出。
3. 日榜、all-time、百萬資格與 audit 交易／冪等；定案不能越過 2 小時 grace；同分、跨午夜、舊版與 staging 隔離。若需延後結算工作，以事件／受限批次續跑，先記游標，不新增高頻空跑。
4. 完成英雄館 UI、HUD、證書圖與實測分享降級；雙語／ARIA／隱私文案逐項審查。
5. 在既有私人 staging 部署完整套件，核對 deployed code、contract、資料持久性、live behavior。測試每日榜刪除、長期公開撤回、證書失效後重試不復活，以及低分／重複領取不污染榜單。
6. 完成原生百萬實玩與錄影後再評審；真人初玩／多人與跨日觀察仍是既有 9 分目標的證據需求，不因增加英雄館而自動通過。
7. 合併／正式發布時，所有前後端同版、Privacy／Terms／README 與外部投稿狀態同輪更新；新留存告知與實際部署不一致視為發布阻塞。

## 自審

- 百萬值只是一個候選計分模型的離線試算，沒有記錄為已達標。
- 私人與正式、當日與長期、不同規則賽季均有清楚範圍；歷史資料不憑空補造。
- 長期名稱保留與原 30 天告知不同，已列明新同意與刪除要求，不能只改前端。
- K 的稱號、真實帳號、AI 示範標記及首位順序均明確，不為錄影破壞公平性。
- 分享支援為平台能力依賴，包含功能偵測與降級，不保證未測試的自動發文。
- 此為新增功能設計核准點；原 v0.51 候選技術成果與四項 9 分證據要求持續保留。
